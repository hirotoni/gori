成果の合否のレビューの委任は、この能力の対象外である。
レビューは `tools/records/review` が依頼文を組み立てて委任する。

依頼文には、次の六項目を見出しとして置く。
委任先はこの依頼文だけを頼りに動くので、委任元の会話で決めたことも書く。

- **目的**：何のための仕事か。
- **範囲**：触ってよいファイルや対象と、触らないもの。
- **受け入れ基準**：何が満たされれば終わりか。一つずつ確かめられる形で書く。
- **検証方法**：受け入れ基準を確かめるコマンドと、期待する出力。
- **禁止事項**：してはならない操作（commit、push、範囲の外の変更など）。
- **報告の形式**：何を返すか。確かめた出力は要約せずに貼らせる。

実装を委任するときは、委任先に `agents/implementer` を使う。
ファイルを書く委任先には、専用の git worktree を作業場所として与える。
同じ作業ツリーに二人が書くと、互いの変更を上書きし、どの変更を確かめたか分からなくなるためである。

委任先の報告は、そのまま人間に渡さない。
委任元が変更と出力を自分で読み、自分の言葉でまとめる。

新しい仕事には新しい委任先を立て、前の委任先の会話を引き継がない。
引き継いだ会話では、途中の指示が抜け落ちやすいためである。
