このセッションは、無人の作業の窓口である。
窓口は会話の中に状態を持たない。人間に伝える前と、指示を受けたときは、毎回 `status` を読み直す。

## 1. 立ち上げ

1. `${CLAUDE_PLUGIN_ROOT}/tools/auto/status` を実行し、出力を人間に短く伝える。対応が要るものが無ければ、無いと一文で伝える。
2. `${CLAUDE_PLUGIN_ROOT}/tools/auto/watch` を、Bash の `run_in_background` で起動する。フォアグラウンドで待たない。
3. 見回りを始めたことを一文で伝えて、人間の入力を待つ。出力を読みに行かず、待つための命令も走らせない。見回りが終わると、このセッションが起こされる。

見回りはモデルを使わない。`todo` の一件を選ぶのも、上限を確かめるのも、`tools/auto/run` である（値は `config/auto`）。

## 2. 見回りが終わったとき

出力の最後の行の `RESULT=` と、その前の一覧を読み、何が起きたかを人間に短く伝える。
一覧の作業 ID と commit は省かない。人間が次に指示するときに使うためである。

| RESULT | 伝えること | 見回り |
| --- | --- | --- |
| pass | 取り込み待ちの作業ができた | 起動し直す |
| merged-left | 学びを無人で取り込んだが、その後の記録に残ったことがある。残ったことと作業 ID | 起動し直す |
| stopped | 人間を待って止まった作業と、その理由 | 起動し直す |
| daily-limit | 今日の上限に達した。今日はもう始まらない | 起動し直さない |
| failed | 失敗の理由と、実行の記録の場所 | 起動し直さない |

終了コード 2（設定を読めない）と、`RESULT=` の行が無い終わり方は、failed と同じに扱う。
failed の後は、人間が原因に対応して、見回りを頼み直すまで起動しない。同じ失敗を繰り返して上限を使い切らないためである。

## 3. 人間の指示

- **取り込み**：取り込み待ちの作業を頼まれたら、まず `git diff <main>...<作業ID>` の要点と、レビュー結果（`${CLAUDE_PLUGIN_ROOT}/tools/records/verdict check --task <作業ID>`）を人間に示す。人間が取り込むと答えたら、`skills/work-branch` の渡す手順で進める。無人の作業が残した手順（main に取り込む手順、プールの一件を done にする手順）は、ここで済みにする。
- **再開**：止まった作業を頼まれたら、`skills/resume` で続きから進める。受け入れ条件を直す必要があって止まった作業は、直した条件を人間に示して承認を得てから進める。
- **見回りの頼み直し**：failed か daily-limit の後に頼まれたら、手順 1 からやり直す。
- **それ以外の依頼**：窓口の外の作業である。振り分けの指示に従って、ふつうの作業として進める。

push と PR の作成は、人間が指示したときだけ行う（`criteria/autonomy`）。

## 禁止事項

- `tools/auto/run` を、窓口のモデルが直接呼ばない。見回りが呼ぶ。
- 見回りを二つ同時に走らせない。起動し直す前に、前の見回りが終わっていることを確かめる。
- 人間が答える前に、取り込み待ちの作業を取り込まない。
