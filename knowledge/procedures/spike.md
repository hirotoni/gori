## 対象

設計や技術の問いに、捨てる前提の試作を作って動かし、観察で答える作業。
成果は問いへの答えであり、コードではない。
コードを読むだけで答えられる問いは `procedures/investigation` で進める。

## 手順

1. 試作で答える問いを一文で書き、何を観察すれば答えになるかを決める。案を比べるなら、比べる観点を作る前に書く（`criteria/prototype-alternatives`）。問いごとに「答えが、決めた観察で裏づけられている」を accept 行に記録する。
2. 作るものと作らないものを人間に示し、承認を得る。
3. 作業 ID の worktree で、問いに答える最小の実装をする。問いに関わらない仕上げ（エラー処理、テスト、整形）はしない。
4. 試作を動かし、手順 1 で決めた観察を取る。
5. 問いへの答えと、観察を再現する手順を、試作のブランチの文書に書く。観察で確かめた点と推測を分ける。
6. commit し、`criteria/done` に従ってレビューを依頼する。レビュアーが確かめるのは答えであり、試作のコードの仕上がりではない。
7. 採る案があれば、`procedures/feature` で作り直す範囲を示す。試作のブランチを残すか消すかと、答えの文書を残す場所を、人間に尋ねる。

## 禁止事項

- 試作のコードを main に取り込まない。PR にしない。
- 観察していないことを、答えに書かない。
- 人間に確かめずに、問いを増やして範囲を広げない。

## 終わりの条件

問いへの答えがあり、各結論に観察（コマンドとその出力）が付いていて、`verdict check` が終了コード 0 を返している。試作のコードは main に入っていない。

## 報告

- 問いと答え。
- 結論ごとの観察と、再現する手順。
- 推測と明記した点。
- 作り直す範囲と、試作のブランチの名前。
